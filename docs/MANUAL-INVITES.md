# Manual invitation accounting — 1.6.2

With AE enabled and debug off, manual invitations through the native party API are observed even if the customer's request is not whitelisted. Ordinary right-click Invite and /invite use C_PartyInfo.InviteUnit in the reviewed Forever UI source. A secure post-hook observes the call after native invocation, including explicit confirmation calls; it never replaces, blocks, resends or confirms an invite. The existing automatic call queue prevents double counting. If an outgoing localized sent message is visible but no hook is observed, that message can create a manual/external record. External callers (including other addons) cannot always be distinguished from manual calls. Incoming invites, arbitrary group joins, and other players' invitations are not automatically treated as customers. Battle.net or internal paths may be missed if neither observable hook nor named outgoing evidence fires.

Manual invitations are intentionally not blocked by the auto blacklist. You can manually choose to invite a restricted customer; if verified, their outcome and completed trade contribute to the same history. New visits are not recorded while AE off or debug on. Existing visits continue passive reconciliation.

Known full-name GUID from a currently observable unit or recent chat enables immediate GUID accounting. Conflicting cached identities are not used. Without a GUID, create a provisional name-only record (shown as manual? in history), track attributable native outcomes and wait for an exact unique full-name home-roster match. Never match surname guesses. On join, move that pending visit into the existing GUID customer's history and count acceptance once. Prior unresolved name-only declines remain separate and never impose identity-based penalties. No trade is attributed without accepted GUID. Known GUID manual declines, no-trade departures, tips and non-tipping policy use existing verified rules. Grouped/busy/ambiguous outcomes never count as verified declines. Pending manual names suppress overlapping automatic calls.

The normal configured welcome, self-marker and raid behavior remain available for an observed manual acceptance. A guild invite whisper is attempted only if the GUID and guild membership are already known when the manual invite is observed; if unknown, do not whisper late on join. Guild non-tipping exemption uses verified membership at service, including when an unknown identity becomes known on acceptance. Empty whisper remains disabled.

Dashboard Overview separates manual/external and automatic counts; Customers history and TSV export label source and uncertain identity. /ae ledgerstatus reports observer hook count, observed manual requests, sent-message fallback and errors. /ae performance remains automatic calls only. No new configuration is required, no schema bump. Existing source-less visits are treated as automatic.
