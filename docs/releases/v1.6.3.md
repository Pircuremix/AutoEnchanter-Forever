# AutoEnchanter 1.6.3 — Marker confirmation and diagnostics

Fixes the immediate read-after-request assumption reported in live play with auto-marker enabled and Star selected. A native marker call can return before the mark is observable, or may fail to apply. Exact cause of the reported missing mark has not yet been established.

- If roster identity/markers are temporarily unreadable or CanBeRaidTarget reports false, wait 0.35 seconds and recheck once **before** the first native call.
- If native SetRaidTarget returns without an observable marker, wait for RAID_TARGET_UPDATE or a one-second timeout before sending welcome. Never claim the configured icon without observing it; never retry an issued call.
- Batch pending welcomes behind one marker request; preserve existing and occupied marks, recheck membership and channel, respect off/debug and raid conversion.
- /ae groupstatus now reports current actual marker, confirmed/unconfirmed calls and the last marker reason.
- Regression coverage for delayed assignment, silent failure, roster settling, preservation, duplicate events and cancellation. No changes to whitelist, customer ledger, guild policy, saved settings or pre-invite processing.

Update in WowUp and restart WoW. Enable /ae marker 1 and /ae debug off, invite a consenting customer with no marker. If the icon is still missing, send redacted /ae groupstatus output. Native API restrictions cannot be bypassed. Live confirmation remains pending.
